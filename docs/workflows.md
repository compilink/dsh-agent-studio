# 任务流程

在 Studio 首页新建一个协作，然后打开「任务流程」。流程模板可用于多个协作。每次启动都属于指定的 Run，使用该 Run 的 Orchestrator、委派权限和 Worker 容量。

## 建图和发布

在画布空白处右键会在指针位置添加节点。右键点击节点可打开设置或删除，节点面板可以修改执行指令。从节点右侧的连接点拖到目标节点即可连线，也可以在下方勾选目标节点的上游。可以在同一张图中保留多个入口和平行分支。草稿可以保留尚未填写指令的节点。发布前，每个节点都需要执行指令。修改会自动保存到草稿，切换模板时会等候该次保存完成。保存会检查重复节点、无效连线和环。不同窗口的修改发生冲突时，页面保留本地编辑并提示重新载入，服务器已有的草稿保持有效。只有点击「发布版本」才会为新实例提供新版。

在模板旁选择历史版本并点击「恢复为草稿」，可以继续修改该版画布。停用模板会禁止新建实例和修改草稿，已发布版本、历史结果和在途执行继续保留。需要时可以重新启用。

节点默认沿用协作的编排策略。选择特定 Agent 时，发布会固定该模板当时的配置版本。Worker 受执行组委派权限约束，Manager 需要协作允许分层推进。选择 Orchestrator 时，协作须由相同模板版本建立。变更 Agent 配置后可以再发布一个流程版本，已有实例继续使用启动时的版本。

## 输入文件与检查规则

先在「流程执行」选择协作和模板版本，再选择接收附件的节点。可以一次选择或拖入多个 UTF-8 文本文件，在启动前逐个撤下。附件跟随本次实例和指定节点，重跑时继续使用该实例的附件。切换协作或版本会显示该组合自己的待上传清单，刷新页面会清空尚未启动的附件。进行中的实例有独立的输入快照。

节点设置中可以分别填写输入和输出检查规则，每行一条。输入检查读取该节点的附件正文和已经放行的直接上游结果。例如，`至少 2 份输入材料` 要求两份输入，`必须包含「授权说明」` 要求正文中出现指定短语。输出检查读取当前结果，例如 `非空`、`至少 50 字` 或 `不得包含「待确认」`。其他自然语言条件由绑定节点的模型检查，沿用协作编排时使用该 Run 的 Orchestrator 模型。离线演示可执行上述固定格式规则。无法判定的条件不会自动放行。

输入检查失败时节点不会派工。输出检查失败会显示原因并进入待审，人工修改后放行前会再次检查。已开始的输出检查需要等待结果再操作节点。

## 交接和复核

选择协作和已发布的版本，点击「启动此版本」。所有无前置依赖的节点可进入现有 Task 调度器。后继节点会等待所有上游产生非空结果并放行，再将各上游结果作为输入正文交给新的 Task。实例会保留上游节点的执行轮次和 Task 引用。有 Worker Attempt 的结果也会记录 Attempt ID。协作、任务、容器和记忆的授权继续适用。

启用「完成后人工审核」时，展开节点可对结果直接修改后放行，或写下意见退回。退回后重跑本节点及下游，重跑指令会带上退修意见和上一轮结果。每一轮已放行的结果都可以在节点中下载为 Markdown 或 Word。若人工修改后放行，导出保留修改后的正文。重跑后展开「历史执行」即可下载之前放行的轮次。已派发的下游仍在运行时，重跑请求会提示等待，其他独立分支继续执行。

流程草稿、已发布版本、实例、审核结果和执行轮次保存在 Studio 的 SQLite 数据库。重启会从最后保存的状态继续检查就绪节点。上游交接的是结果正文。容器文件可在协作的 Attempt 中查看。

## 验证

`npm run check` 包含依赖图、版本、权限、重启恢复和人工放行的测试。如果本机已安装 Playwright 和 Chromium，还可以在构建后用 `node scripts/check-workflow-ui.mjs` 验证浏览器中的建图、拖线、审批和交接。浏览器检查使用临时目录和独立端口。
